# 🛡️ Crystal Heimdall — Security Policy & Operator Access Model

> **🔒 CLASSIFICATION: PROPRIETARY & CONFIDENTIAL // FOR INTERNAL USE ONLY**  
> **PROPERTY OF CRYSTAL STUDIO LABS — ALL RIGHTS RESERVED.**  
> *Security Philosophy: Extreme Simplicity, Cryptographic Determinism & Zero Third-Party Dependencies.*

---

## 1. Private Repository Classification & Access Control

Crystal Heimdall is an internal infrastructure sentinel. The codebase, architectural topology, and telemetry databases are strictly proprietary:

1. **Organization-Level Access:** Access is restricted to vetted Crystal Studio Labs engineering personnel.
2. **Perimeter Segregation:** 
   * **Public Tier:** The Status Page (`/`) and Incident Ledger (`/incidents`) are publicly visible for transparency.
   * **Private Tier:** The Operator Command Deck (`/dashboard*`) and management APIs (`/api/v1/services*`, `/api/v1/status/settings*`) must be restricted to internal corporate subnets, Tailscale mesh, or Cloudflare Zero Trust.
3. **Search Engine Protection:** Crawler exclusion is enforced across all private operator endpoints via `robots.txt` disallows and dynamic `<meta name="robots" content="noindex, nofollow" />` tags.

---

## 2. Operator Authentication: 2FA-Only Policy

Crystal Heimdall enforces a **Strict 2FA-Only Authentication Gate** (`/login`) for operator deck access:

1. **Zero Master Passcodes:**
   - There are no database-stored administrative passwords, password reset email flows, or credential leak vulnerabilities.
2. **Zero Third-Party OAuth Dependencies:**
   - Does not rely on GitHub, Google, or external identity providers. If third-party OAuth providers experience downtime, your monitoring system will never lock you out.
3. **RFC 6238 TOTP Standards:**
   - Operators authenticate via a rolling 6-digit Time-based One-Time Password generated by standard authenticator apps (Ente Auth, 1Password, Google Authenticator).
   - In offline development and test environments, emergency code `000000` is accepted for automation testing.

---

## 3. Secret & Credential Management Policy

1. **Zero Hardcoded Secrets:**
   * All cryptographic secrets (`JWT_SECRET`, `TOTP_SECRET`, database URIs, webhook credentials) must be provisioned via environment variables (`.env`).
   * Committing `.env` or production credentials to git is grounds for immediate credential revocation and internal security audit.
2. **Secret Storage:**
   * Production and staging environment variables are securely stored in the internal **Crystal Studio Labs 1Password / Vault** vault (`Engineering > Crystal-Heimdall`).
3. **Inbound Service Token Isolation:**
   - Every monitored target is provisioned with an isolated high-entropy API key (`svc-key-...`).
   - External reporting services authenticate via HTTP Authorization header:
     ```http
     Authorization: Bearer svc-key-xxxxxxxxxxxx
     ```
   - Compromising an individual worker's key permits reporting only for that single target; it grants zero administrative command rights over the sentinel deck.

## 4. Threat Mitigation & Hardening Matrix

| Vector | Mitigation Strategy |
|---|---|
| **Alert Storms & Cascading Failures** | 15-minute sliding window deduplication suppresses duplicate alerts while silently tracking event frequencies. |
| **Search Engine Scraping** | Private operator routes (`/dashboard`, `/dashboard/*`, `/api/`) are strictly disallowed in `robots.txt` and flagged with `<meta name="robots" content="noindex, nofollow" />`. |
| **Man-In-The-Middle Attacks** | Enforces TLS/SSL certificate validation. Configurable expiration window (default: 30 days) triggers early warnings before cert expirations. |
| **Telemetry Bloat & Resource Starvation** | Telemetry points older than configured retention period (default: 30 days) can be pruned via `POST /api/v1/status/purge-data`. |
| **Session Hijacking** | Signed JWT operator tokens with strict expiration and cryptographic validation against `JWT_SECRET`. |

## 5. Internal Security Incident & Disclosure Protocol

For internal security vulnerabilities or potential token compromises:
* **Contact:** Direct urgent security reports to the Crystal Studio Labs Security Response Team via `security@crystalstudio.labs` or internal Telegram security dispatch.
* **Triage SLA:** Critical vulnerabilities are reviewed and triaged within 4 hours.
* **Secret Rotation:** If an operator token or monitor API key is suspected to be compromised, execute immediate token regeneration inside `/dashboard/settings`.
