## 1. Classification & Perimeter Access Control

Crystal Heimdall is engineered as an enterprise-grade infrastructure sentinel. The perimeter is separated into three security rings:

1. **Ring 0 — Cryptographic Operator Deck (`/dashboard*`, `/api/v1/services*`):**
   * Accessible only after authenticating via rolling RFC 6238 TOTP.
   * Signed, time-bounded HMAC-SHA256 JWT tokens.
   * Navigation links to the command deck are strictly hidden from unauthenticated visitors on both desktop and mobile viewports.
2. **Ring 1 — Isolated Service Reporting Conduits (`/api/v1/ping/:key`):**
   * Inbound reporting microservices authenticate via high-entropy isolated bearer tokens (`svc-key-xxxxxxxxxxxx`).
   * Compromise of an individual reporting key grants zero access to the operator command deck or other monitors.
3. **Ring 2 — Public Telemetry & Status Hub (`/`, `/docs`, `/incidents`):**
   * Read-only public surfaces for public status transparency, incident postmortems, and dynamic SVG availability shields.
   * All administrative control endpoints are excluded from web crawlers via `robots.txt` and `<meta name="robots" content="noindex, nofollow" />`.

---

## 2. Operator Authentication: 2FA-Only Policy

Crystal Heimdall enforces a **Strict 2FA-Only Authentication Gate** (`/login`):

1. **Zero Master Passcodes:**
   - There are zero database-stored administrative passwords, zero password reset email workflows, and zero credential leak vulnerabilities.
2. **Zero Third-Party OAuth Downtime:**
   - Heimdall does not rely on GitHub, Google, or external identity providers. If third-party OAuth providers experience downtime, your monitoring system will never lock you out.
3. **RFC 6238 TOTP Standard:**
   - Operators authenticate via a rolling 6-digit Time-based One-Time Password generated by standard authenticator apps (Ente Auth, 1Password, Google Authenticator).
   - In local development or isolated testing environments, emergency code `000000` is accepted for automation test suites.

---

## 3. Cryptographic Storage & Secrets Policy

1. **AES-256-GCM Encrypted Persistence:**
   * Sensitive operator authentication secrets, private VAPID keypairs, and subscriber endpoint tokens are encrypted at rest using AES-256-GCM authenticated cipher blocks.
2. **Zero Hardcoded Secrets:**
   * All cryptographic keys (`JWT_SECRET`, `TOTP_SECRET`, `SESSION_SECRET`, database URIs, webhook credentials) must be provisioned via environment variables (`.env`).
   * Committing `.env` or production credentials to git is grounds for immediate credential revocation and internal security audit.
3. **Timing-Safe String Comparisons:**
   * All cryptographic hash comparisons, API token verifications, and TOTP checks use `crypto.timingSafeEqual()` to completely neutralize side-channel timing attacks.

## 4. Threat Mitigation & Hardening Matrix (43-Point Pentest Verified)

| Threat Vector | Mitigation Strategy | Verification |
|---|---|---|
| **SQL Injection (SQLi)** | Parameterized queries exclusively via `@libsql/client` and `better-sqlite3`. Zero raw string concatenation. | 43/43 Pentest Suite |
| **Cross-Site Scripting (XSS)** | React JSX auto-escaping, HTML sanitization on incident descriptions, strict CSP headers. | 43/43 Pentest Suite |
| **Alert Storms & Cascades** | 15-minute sliding window deduplication suppresses duplicate alerts while silently tracking event frequencies. | Test #33 Smoke Suite |
| **Search Engine Scraping** | Private operator routes (`/dashboard`, `/dashboard/*`, `/api/`) are strictly disallowed in `robots.txt` and flagged with `<meta name="robots" content="noindex, nofollow" />`. | Test #24 Smoke Suite |
| **Man-In-The-Middle (MitM)** | Enforces strict TLS/SSL certificate validation. Configurable expiration window (default: 30 days) triggers early warnings before cert expirations. | Test #14 Smoke Suite |
| **Brute Force & DoS** | Rate-limiting middleware on auth gate, payload size caps (`100kb`), and sliding window request caps. | 43/43 Pentest Suite |
| **Web Push Spoofing** | RFC 8292 VAPID cryptographic signatures and claims (`mailto:` contact URI verification). | Test #39 Smoke Suite |

## 5. Security Vulnerability Reporting Protocol

If you discover a security vulnerability or potential token leak within Crystal Heimdall:
* **Contact:** Direct urgent security reports to the Crystal Studio Labs Security Response Team via `security@crystalstudio.labs` or internal Telegram security dispatch.
* **Triage SLA:** Critical vulnerabilities are reviewed and triaged within 4 hours.
* **Secret Rotation:** If an operator token or monitor API key is suspected to be compromised, execute immediate token regeneration inside `/dashboard/settings`.
